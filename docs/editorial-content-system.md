# Sistema editorial escalável — Opinião Real

## Objetivo

O Opinião Real deve operar como uma revista especializada em decisões de compra: conteúdo útil, comparações verificáveis, SEO técnico e CTAs comerciais transparentes.

A regra central é simples: **escala de produção não pode significar escala de conteúdo genérico**.

## Tipos oficiais de conteúdo

### 1. Review de Produto

Use para consultas com intenção comercial.

Estrutura obrigatória:

1. Título orientado à decisão
2. Introdução: problema, contexto, escopo e promessa editorial
3. Caixa **Melhores escolhas**
   - Melhor escolha geral
   - Melhor custo-benefício
   - Melhor para iniciantes
   - Melhor para espaços pequenos
4. Comparativo lado a lado
5. Análise individual de cada produto
   - Nome
   - Imagem real
   - Resumo
   - Ideal para
   - Pontos positivos
   - Pontos negativos
   - Nossa avaliação
   - CTA **Ver preço atualizado**
6. Como escolher
7. FAQ com 5–8 perguntas reais
8. Conclusão por perfil
9. Veja também
10. Aviso de afiliados

### 2. Guia Informativo

Use para dúvidas educativas e consultas de descoberta.

Estrutura:

1. Introdução
2. Explicação simples
3. Benefícios
4. Desvantagens e limitações
5. Comparações quando ajudarem a decisão
6. FAQ
7. Veja também, priorizando a página comercial do cluster

### 3. Comparação A vs B

Use quando o usuário já reduziu a decisão para dois produtos.

Estrutura:

1. Introdução curta
2. Comparação direta
3. Tabela com preço, características, qualidade e indicação
4. Vantagens e desvantagens de cada opção
5. Qual escolher?
6. FAQ
7. Veja também
8. CTA comercial, quando houver links de afiliado verificáveis

## Contrato SEO

Todo artigo precisa ter:

- slug curto e descritivo;
- meta title específico para a intenção de busca;
- meta description informativa, sem clickbait;
- um único H1;
- H2/H3 em ordem lógica;
- imagens relevantes com alt text descritivo;
- breadcrumbs;
- canonical;
- Schema.org adequado ao conteúdo;
- FAQ visível quando houver perguntas frequentes;
- links internos contextuais.

Não publicar schema que descreva conteúdo que não existe na página.

## Linkagem interna e clusters

Cada artigo deve apontar para a página principal comercial do seu cluster e para conteúdos de apoio relevantes.

### Fitness

**Pilar:** `/melhores-bicicletas-spinning`

Apoio:

- `/bicicleta-spinning-vale-a-pena`
- `/bicicleta-spinning-apartamento`
- `/bicicleta-spinning-emagrece`
- `/como-escolher-bicicleta-spinning`

### Esteiras

**Pilar:** `/melhores-esteiras-dobraveis`

Apoio planejado:

- `/esteira-vale-a-pena`
- `/esteira-dobravel-para-apartamento`
- `/esteira-eletrica-ou-mecanica`

### Ferramentas

**Pilar:** `/melhores-kits-ferramentas`

Apoio planejado:

- `/melhor-parafusadeira`
- `/kit-ferramentas-para-casa`
- `/ferramenta-sem-fio-vale-a-pena`

Todo artigo deve terminar com um bloco **Veja também** ou **Leia também**, com pelo menos um link para o pilar quando esse pilar existir.

## Como analisamos

Reviews e comparativos devem incluir um bloco editorial explicando os critérios usados:

- pesquisa de características;
- comparação de modelos;
- análise de avaliações de consumidores, quando disponíveis e verificáveis;
- análise de custo-benefício.

Não usar essa seção para alegar testes físicos que não foram realizados.

## Contrato de afiliados

Todo link comercial deve ser identificável e rastreável. O contrato técnico exige:

- `data-affiliate="true"`;
- `data-product-id`;
- `data-product-name`;
- `data-cta-position`.

O evento esperado é `affiliate_click`.

A posição deve permitir distinguir, por exemplo, `hero`, `ranking-1`, `table-1`, `detail-1` e `final`.

Links sem produto real e sem oferta verificável não devem ser tratados como recomendações editoriais.

## Dados comerciais e evidências

Antes da publicação de um review:

1. confirmar nome exato do produto;
2. confirmar fabricante/modelo;
3. conferir especificações em fonte confiável;
4. conferir imagem correspondente ao produto;
5. conferir preço ou apresentar claramente que o preço é variável;
6. conferir disponibilidade quando isso for mencionado;
7. conferir URL de afiliado;
8. registrar data da conferência;
9. revisar pontos positivos e negativos contra evidências reais.

Nunca preencher campos com números fictícios apenas para completar um card ou tabela.

## Calendário editorial

### Prioridade alta

Publicar primeiro quando houver combinação de:

- alta intenção de compra;
- ticket potencial relevante;
- comissão potencial relevante;
- boa correspondência com uma página de produto real.

Exemplos: melhores produtos, comparativos A vs B, "qual comprar" e "vale a pena" com forte intenção comercial.

### Prioridade média

- guias de escolha;
- explicações de critérios;
- conteúdos educativos que ajudam a chegar à decisão.

### Prioridade baixa

- dúvidas muito amplas;
- conteúdos com baixa intenção comercial;
- temas que não conseguem apontar naturalmente para um produto ou cluster.

## Checklist de publicação

### Editorial

- [ ] O artigo responde uma intenção clara.
- [ ] Há evidências para afirmações factuais.
- [ ] Não há descrição copiada do fabricante.
- [ ] Pontos positivos e negativos são justificáveis.
- [ ] O texto deixa claras as limitações da análise.

### SEO

- [ ] Slug amigável.
- [ ] Meta title.
- [ ] Meta description.
- [ ] H1 único.
- [ ] H2/H3 organizados.
- [ ] Breadcrumbs.
- [ ] Canonical.
- [ ] Schema adequado.
- [ ] FAQ visível e coerente com o schema.
- [ ] Alt text das imagens.
- [ ] Links internos.

### Conversão

- [ ] O produto ou decisão recomendada aparece cedo.
- [ ] Existe CTA claro sem urgência artificial.
- [ ] CTA identifica produto e posição.
- [ ] Link de afiliado foi testado.
- [ ] Aviso de afiliado está visível.
- [ ] Não há preço, desconto, estrela, avaliação ou depoimento inventado.

### Experiência

- [ ] Funciona bem no celular.
- [ ] Tabela é legível em telas pequenas.
- [ ] Botões têm área de toque confortável.
- [ ] Imagens não são desnecessariamente pesadas.
- [ ] Navegação interna ajuda a chegar ao trecho desejado.

## Regra de escala

A produção pode crescer de 10 para centenas de URLs sem alterar o padrão porque a estrutura técnica agora está centralizada em `src/content/contentTemplates.js`.

Esse arquivo define os tipos oficiais, campos SEO obrigatórios, estrutura de cada formato, clusters, calendário editorial e contrato de rastreamento de afiliados.

**Princípio de publicação:** se um dado não foi verificado, ele fica ausente ou explicitamente marcado como pendente. Nunca deve ser inventado para preencher o template.
